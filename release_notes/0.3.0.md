# Gabriel

## Correctifs

- **Chaque VRF de VPC porte une route `unreachable default` (#81).** Une recherche qui échouait
  dans la table d'une VRF continuait dans la table `main` de l'hôte : un paquet d'un locataire
  vers une adresse inconnue de son VPC sortait par l'underlay, avec `169.254.0.2` pour source
  (mesuré en lab). La route est posée juste après la VRF, avec la métrique maximale
  `4278198272`, de sorte que toute route réelle reste prioritaire ; elle n'est pas annoncée en
  EVPN et elle est retirée au démontage du VPC. Le watchdog signale une VRF qui ne l'a pas.
  IPv4 seulement
- **`default_route: true` sans `gateway` est réservé au mode `bridge` (#81)** : refusé (400) en
  `vxlan` et en `public_ip`. Hors `bridge`, la gateway lue dans la table de routage de l'hôte
  n'est pas sur le subnet des VM : la route par défaut annoncée était inutilisable
- **La suppression d'une VM retire ses sockets QEMU (#84).** Quand QEMU échouait au démarrage
  (disque absent par exemple), il pouvait laisser `<vm>.sock` dans `serial_dir`, `monitor_dir` ou
  `qmp_dir`, que la suppression de la VM ne retirait pas. Les trois sont désormais supprimés une
  fois QEMU arrêté ; un fichier absent n'est pas une erreur

## Mise à jour depuis la 0.2.0

- **`default_route: true` exige une `gateway` hors mode `bridge`** : un appel qui l'omettait en
  `vxlan` reçoit désormais un 400. Les subnets existants gardent la route par défaut qu'ils
  annonçaient jusqu'à leur recréation
- **Les VPC routés existants n'ont pas la route `unreachable default`** : l'agent ne la pose pas
  au démarrage, le watchdog les signale à chaque tick. La recréation du VPC la pose ; d'ici là,
  la fuite vers l'underlay décrite plus haut reste possible. Pour la fermer sans recréer le VPC,
  la poser à la main sur chaque hyperviseur, la table étant le `l3vni` du VPC :
  `ip route replace unreachable default metric 4278198272 table <l3vni>`
